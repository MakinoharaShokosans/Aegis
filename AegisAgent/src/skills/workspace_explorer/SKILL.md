# 工作区结构与文件职责勘测标准作业程序 (SOP)

> 本 SOP 旨在指导 Agent 高效、低开销、证据确凿地完成物理工作区勘测，杜绝琐碎的多轮单独读取，确保 1~2 轮动作内输出高质量全景报告。

---

## 1. 核心原则与反模式 (Anti-Patterns)

### ❌ 严禁的反模式
1. **严禁单文件碎步读取**：对目录内 3 个以上的小文件，严禁连续发起多轮单文件 `cat` 或 `view_file` 命令，这会急剧消耗 LLM 轮次与 Context 预算。
2. **严禁遍历深层构建噪音**：必须主动排除 `.git`、`node_modules`、`target`、`__pycache__`、`.venv`、`dist`、`build`、`.pytest_cache` 等噪音目录。
3. **严禁凭空脑补职责**：文件职责描述必须基于文件头注释、导出接口、入口调用或实际内容证据，严禁仅凭文件名做脱离事实的猜测。

### ✔️ 推荐的最佳实践
1. **先宏观拓扑，后局部深挖**：先通过 2 层深度的目录过滤扫描建立全貌，再按需针对关键文件采样。
2. **小文件批量聚合提取**：对小型工作区（文件数 $\le 10$），优先采用一行复合命令获取全部有效文件的头 25 行内容。
3. **关键技术栈入口优先**：如果是标准工程项目，优先查阅根目录清单与配置文件（如 `README.md`、`pyproject.toml`、`package.json`、`Cargo.toml`、`CMakeLists.txt`、`index.html`）。

---

## 2. 标准执行工作流 (Standard Workflow)

### 阶段一：浅层拓扑与文件过滤扫描
优先使用带排除规则的 `find` 或 `git ls-files` 获取工作区 2 层深度内的有效文件列表：

```bash
# 推荐命令：扫描根目录及一阶子目录，排除隐藏目录与常见依赖产物
find . -maxdepth 2 -not -path '*/.*' -not -path '*/node_modules/*' -not -path '*/__pycache__*' -not -path '*/.venv/*' -not -path '*/target/*' -not -path '*/dist/*' | sort
```

### 阶段二：差异化特征采样

根据阶段一发现的文件特征选择策略：

#### 场景 A：小型工作区 / 扁平目录（有效文件 $\le 10$ 个）
直接执行单条聚合脚本，批量获取文件类型与前 25 行摘要：
```bash
for f in $(find . -maxdepth 2 -type f -not -path '*/.*' -not -path '*/node_modules/*' -not -path '*/__pycache__*' | sort); do
    echo "==================== [FILE: $f] ===================="
    file -b "$f"
    head -n 25 "$f"
    echo ""
done
```

#### 场景 B：标准软件工程仓库（多模块/深层代码库）
1. **第一优先级（项目定位）**：读取根目录 `README.md` 与配置入口（如 `pyproject.toml`, `Cargo.toml`, `package.json` 等）。
2. **第二优先级（模块划分）**：列出核心源码目录（如 `src/` 或根包）的一级子模块/包名。
3. **第三优先级（核心组件）**：使用 `view_file` 读取各核心子模块的 `__init__.py` 或主要入口文件。

## 3. 交付输出规范 (Delivery Matrix)

在总结交付给用户时，必须严格组织为结构化的 Markdown 报告，包含：

### 1. 工作区全景速览
- **项目定位**：一句话说明该工作区/项目的核心性质（如：*前端演示原型* / *Python 微服务运行时* / *文档与草稿知识库*）。
- **技术栈**：主要语言与核心框架。

### 2. 文件职责矩阵表
| 相对路径 | 文件类型 | 核心职责与功能定位 | 关键依赖 / 关联入口 | 状态与备注 |
| :--- | :--- | :--- | :--- | :--- |
| `index.html` | 前端页面 | 单页面交互自测界面，提供基础 UI 控制 | 依赖原生 CSS/JS | 可直接在浏览器打开运行 |
| `README.md` | 说明文档 | 项目介绍、安装步骤与快速上手指南 | - | 官方核心文档 |

### 3. 架构与依赖流转简述（适用于多文件工程）
简要说明文件/模块之间的调用关系与数据流动方向。
