## 2. 金标数据集概况 (Evaluation Dataset)

- **数据集路径**：`AegisAgent/src/evaluation/rag_bench/datasets/aegis_code_eval.jsonl`
- **用例总数**：20 条（共触发 $20 \times 4 = 80$ 次真实检索请求）
- **分类分布**：严格遵循 4:4:2 的三层用例分类体系：
  - **Category A：符号精确查找 (Symbol Precision)**（8 条，40%）：覆盖 `point_id_for`、`PreflightRunner`、`EmbeddingPipeline`、`QdrantStore`、`split_ast`、`Reranker` 等核心符号；
  - **Category B：功能与逻辑定位 (Semantic Implementation)**（8 条，40%）：覆盖维度强校验、UUIDv5 幂等去重、陈旧切片清理、内存沙箱冒烟、语法降级等实现逻辑；
  - **Category C：跨文件概念与架构 (Cross-file Concept)**（4 条，20%）：覆盖双路召回与 RRF 融合、Markdown CCH 面包屑注入、七维启动体检矩阵、精排与低置信度标记等跨文件机制。

## 4. 核心指标归因与架构设计验证 (Architectural Insights)

### 4.1 Cross-Encoder 精排正向增益分析

- **核心数据**：
  - **MRR@3**：从 `hybrid_rrf` 的 $0.3250$ 提升至 `hybrid_rerank` 的 $0.5000$（**相对提升 +53.8%**）；
  - **MRR@5**：从 `hybrid_rrf` 的 $0.3500$ 提升至 `hybrid_rerank` 的 $0.5125$（**相对提升 +46.4%**）；
  - **NDCG@5**：从 `hybrid_rrf` 的 $0.3632$ 提升至 `hybrid_rerank` 的 $0.5432$（**相对提升 +49.6%**）。
- **技术归因**：
  RRF 倒排融合虽然能够兼顾 Dense 与 Sparse 两路的排名，但本质上只是基于 rank 倒数的简单数学加权，无法感知 query 与候选切片之间的深层语义交互。Cross-Encoder 精排模型通过跨文本注意力机制对 30 个初筛候选进行深度重打分，成功将最相关的黄金切片大幅推至 Top-1 和 Top-3，极大提升了智能体“第一眼”获取正确上下文的概率。

### 4.2 双路召回互补性分析

- **Sparse BM25 的独特定位**：
  在纯符号查找类用例中，BM25 展现出毫秒级的响应（541ms 端到端耗时），能以极高的精度匹配 AST 切分后的精确符号名（函数名、类名、变量名）；
- **Dense 语义的泛化兜底**：
  在自然语言功能意图描述（如“启动期强校验”、“增量切片去重”）中，Dense 向量展现出强劲的语义联想能力，HitRate@10 达到 0.8000；
- **融合互补**：
  两路结合在经过 Cross-Encoder 筛选后，在 Top-3 实现了 0.7000 的高命中率。

## 6. 结论与后续演进建议

1. **评测体系固化**：
   本次建立的 SOP、标注集契约与离线评测驱动器已被完全固化，后续任何切分策略调整（如引入 Tree-sitter 其他语言解析器）、模型换代或 RSE/MMR 等增强项落地，均应以此基准进行自动化 A/B 回归评测。
2. **性能与时延优化方向**：
   当前本地 CPU 推理模式下，Cross-Encoder 对 30 个候选进行深度打分导致平均时延约为 7000ms。生产环境下推荐：
   - **方案 A (GPU 加速)**：在具备 CUDA/MPS 环境的机器上启用 ONNX Runtime GPU 执行提供器，可将精排耗时压缩至 100ms 以内；
   - **方案 B (远端 API 切换)**：切换为 `rerank.mode = "remote"` 走高速推理网关（`api.openlux.ai`），降低本地 CPU 负载；
   - **方案 C (初筛数量动态调整)**：将 `fusion_top_k` 从 30 适度调整至 15~20，可在几乎不损失精度的前提下减少约 40% 的精排计算耗时。
