# Aegis 系统全景技术栈清单 (Tech Stack BOM)

> **版本**：v0.8 (涵盖 Agent Runtime、外部检索隔离、HTTP 接入层、RAG 混合检索与基础设施)  
> **定位**：Aegis (Engineering Research Agent) 落地实施的技术栈速查表与核心依赖清单。  
> **v0.8 修订**：新增「外部检索隔离层」：网络抓取能力从主 Agent 工具表剥离至研究子智能体，建立不可信数据信任边界。  
> **v0.7 修订**：`mcp` 与 `langgraph-checkpoint-sqlite` 已实际声明并锁定于 `uv.lock`；依赖清单结构重整为 8 组。  
> **v0.6 修订**：新增 Agent HTTP API 接入层（`:8000`，契约见 `agent_runtime/11_http_api.md`）；明确 `bash_shell` / `web_search` 为同工程子系统而非独立子工程。  
> **v0.5 修订**：① 依赖清单版本下限与 `AegisAgent/uv.lock`、`AegisRAG/uv.lock` 实际锁定版本对齐（消除"文档写 0.x、实际装 1.x/3.x"的漂移）；② 澄清 `AsyncSqliteSaver` 属于独立包；③ 统一 dense embedding 模型的默认选择与向量维度。

## 1. 系统全景技术栈矩阵

| 架构分层 | 核心技术 / 库 | 协议 / 模型 / 算法 | 部署 / 运行形态 | 核心职责 |
| :--- | :--- | :--- | :--- | :--- |
| **Agent 编排调度** | **LangGraph** | 有向循环图 (StateGraph) | 进程内 (In-Process) | 任务状态机、分支流转、多轮循环迭代、生命周期管理 |
| **LLM 通信层** | **AsyncOpenAI** + **tenacity** | OpenAI `/v1/chat/completions` | 异步网络客户端 | 多套配置端点（base_url/key/model 独立），故障自动降级切换；支持 429 退避重试 |
| **数据契约与校验** | **Pydantic v2** | JSON Schema / BaseModel | 进程内 (Rust Core) | 全局 `AgentState`、Tool Schema、Trajectory 结构强类型约束 |
| **上下文与预算管理**| **tiktoken** + **trim_messages** | BPE Tokenizer + 三层金字塔裁剪 | 进程内 | 毫秒级本地 Token 计算；Atomic Pair 成对裁剪防 400 崩溃，滚动摘要移出旧消息 |
| **状态快照与断点续跑**| **AsyncSqliteSaver** | SQLite Checkpoint 表 | 本地单文件 (`storage/checkpoints/`) | 任务崩溃重入恢复、Time-Travel 时空穿梭与分支排错 |
| **关系型任务元数据**| **SQLite (aiosqlite)** | WAL 模式 (读写不互斥) | 本地单文件 (`storage/aegis_meta.db`) | 任务状态（PENDING/RUNNING/SUCCESS/FAILED）、消耗与统计信息存储 |
| **微服务与通信底座**| **FastAPI** + **uvicorn** | ASGI / HTTP REST / SSE | 独立进程 (AegisRAG `:8001`、bash_shell `:8002`、web_search `:8003`) | 暴露检索、Shell 执行与 Web 抓取服务接口，统一拦截透传 `X-Trace-ID` |
| **外部检索隔离层**| 自研 Research Subagent | 有界异步循环 + Pydantic 强类型契约 + URL/版本正则白名单 | 同工程进程内 (`agent_runtime/research`) | 隔离不可信网页内容：主工具表构造期拒绝不可信工具，主 Agent 永不接触原始页面，只接收校验后的研究报告 |
| **Agent 接入与前端契约**| **FastAPI** + **uvicorn** + **SSE** | HTTP REST + `text/event-stream` | 同工程内 (`agent_runtime/api`，`127.0.0.1:8000`) | 工作区/会话/任务 REST、任务实时事件流、上下文检视与产物读取；唯一用户入口，供 Web 前端消费（契约见 `11_http_api.md`） |
| **服务间通信客户端**| **httpx** + **asyncio.gather** | HTTP/1.1 & HTTP/2 并发连接池 | 进程内 (Tool Layer) | Agent 访问独立检索与外部 API；单轮多个 tool_calls 并发分发，缩减总耗时 |
| **向量与索引数据库**| **Qdrant** (`qdrant-client`) | HNSW + 倒排索引 (Sparse) | 本地嵌入 (`path`) 或 Docker 单机 | 单库同时存储 Dense 向量与 BM25 稀疏向量，提供 Payload 精准过滤 |
| **稠密向量 (Dense)**| **fastembed** / **OpenAI** | `BAAI/bge-small-en-v1.5` (**384 维**，默认) / `text-embedding-3-small` | 本地 ONNX / API | 语义级向量生成，CPU 极速推理，无需 GPU / PyTorch。中文场景可换 `BAAI/bge-small-zh-v1.5`（**512 维**，须同步改 `vector_size`） |
| **稀疏向量 (Sparse)**| **fastembed** | `Qdrant/bm25` | 本地 ONNX | 专有名词、C/C++ 函数名、系统调用精准词法向量化 |
| **混合召回融合算法**| **Qdrant 内置算子** | **RRF (Reciprocal Rank Fusion)** | 数据库内核级执行 | 倒排互惠融合排序，Top-50 双路候选无缝合并，零 Python 胶水代码 |
| **精排重塑 (Rerank)**| **fastembed.Rerank** | **BAAI/bge-reranker-base** | 本地 ONNX | Cross-Encoder 深度打分，将 50 条粗排压缩至 Top-5，防 Context 膨胀 |
| **代码语法树切分** | **tree-sitter** | C / C++ / Go AST Grammar | 进程内解析 | 代码按函数/结构体语法块完整切片，携带文件名与行号元数据 |
| **文档层级切分** | **MarkdownHeaderTextSplitter** | Header-based Hierarchy | 进程内解析 | 技术规范与手册保留章节层级面包屑上下文 |
| **Bash 执行沙箱** | **asyncio.subprocess** + **os.setsid** + **resource.setrlimit** | 进程组隔离 (PGID) + 内存队列 | 独立微服务 (`services/bash_shell`) | 异步执行 Shell 命令、两段式硬超时熔断 (SIGTERM->SIGKILL)、全局内存池队列管理、孤儿进程清理 |
| **物理资源硬配额** | **resource (setrlimit)** + **GlobalMemoryBudget** | Linux 内核配额 + 应用层协调 | 进程内注入 | 限制最大虚拟内存 2GB、文件大小 50MB、CPU 时间；多任务竞争时排队等待，告知预估时间 |
| **海量输出治理** | **Observation Pruner (自研)** + **StructureAwarePruning** | 观察截断、结构保护、离线卸载 | 进程内 | 全量日志流式写入 `storage/artifacts/`；结构化格式（JSON/YAML）保持完整性，纯文本采用 Head/Tail 提取 |
| **本地结构化日志** | **Loguru** | 异步队列 (`enqueue=True`) | 本地标准输出 + JSON Lines | 全系统结构化日志，自动追加写入本地系统轨 |
| **因果轨迹持久化** | **Trajectory Store (自研)**| JSONL 序列化 | 本地落盘 (`storage/traces/*.jsonl`) | 记录每一步的 Thought、Action、Distilled Observation，供离线 Eval |
| **平台可视化追踪** | **Langfuse** | OpenTelemetry / REST | Docker 容器 (本地暴露 Web UI) | 展示调用树拓扑图、瀑布流 (Waterfall)、单步耗时与 Token 成本明细 |
| **自动化评测套件** | **pytest** + **pytest-asyncio** | 自动化端到端测试 | 命令行 / CI/CD | 批量驱动 20~50 个标准工程研究场景，回归测试 Agent 执行表现与断言检查 |
| **IR 检索评测引擎** | **numpy** | HitRate@K, MRR@K, NDCG@K | 进程内离线计算 | 毫秒级计算检索物理质量，零 LLM 消耗，支持双路召回与重排消融实验 |
| **评测报告格式化** | **tabulate** | ASCII / Markdown 表格 | 命令行 / 文件输出 | 自动生成控制台与基准报告对比表格 |
| **Web 搜索引擎** | **duckduckgo-search** + **去重器** | 搜索 API 适配器 + 内容指纹 | 独立微服务 (`services/web_search`) | 零门槛免费开箱即用检索；MD5 内容指纹去重镜像站，可选时效性过滤 |
| **网页正文提炼** | **trafilatura** | 启发式正文提取算法 | 进程内解析 | 剔除导航/页脚/广告噪声，直接输出保留代码块的精炼 Markdown |
| **运行时安全护栏** | **Guardrails (自研双轨熔断)**| MD5 指纹 + 连续错误计数器 | 进程内条件边拦截 | 参数指纹防无脑重复，连续 3 次报错触发重规划，`max_steps` 与费用硬熔断 |

## 3. 技术栈特色与面试核心价值总结

1. **”确定性包围非确定性”**：
   - 上层推理交给 LLM，底层的状态跃迁（LangGraph）、契约校验（Pydantic v2）、状态存储（SQLite WAL）、检索排序（Qdrant RRF）全部是 100% 确定性工程。

2. **轻量、便携、零 GPU 门槛**：
   - 传统 RAG 动辄需要安装数个 G 的 PyTorch 和复杂 CUDA 环境；
   - 本系统采用 **FastEmbed (ONNX)**，几十兆包体积即可在单机 CPU 上高速跑完 Dense Embedding、BM25 Sparse 和 Cross-Encoder Rerank。

3. **单数据库原生混合检索**：
   - 告别”ES + 独立向量库 + 手写排序胶水代码”的混乱架构，基于 Qdrant 单一系统完成 Dense + Sparse + RRF 融合。

4. **本地单机设计与多租户隔离**：
   - **架构定位**：完全本地运行（类似 Claude Code），不依赖服务器部署；
   - **内存管理**：全局内存池 + 任务队列机制，多个 Agent 任务有序执行，单个任务超限时排队等待而不是失败；
   - **配置多套 LLM 源**：每套包含独立的 URL/Key/Model，主源故障自动切换到备用源，确保单机环境下可靠性；
   - **成本可预测**：任务级预算告警，防止单个任务费用失控，所有消耗透明可查。

5. **智能上下文治理**：
   - **结构化感知截断**：JSON/YAML 等结构化输出保持完整，纯文本才采用 Head+Tail 提取，避免破坏语法；
   - **Token 预算动态告警**：实时计算累计成本，接近阈值时主动告警，超出时自动熔断；
   - **观察离线卸载**：全量日志流式写入 `storage/artifacts/`，仅向 Context 注入精炼摘要，防止 Lost in the Middle。

6. **双轨可观测与证据溯源**：
   - 本地系统日志（Loguru + JSONL）支撑自动化评测与故障自愈率统计；
   - 可视化平台（Langfuse Web UI）支撑链路拓扑与时延展示；
   - 实验数据下沉到 Artifacts，报告显式反向引用，实现”结论可查、证据闭环”。

7. **Web 搜索的生产级质量控制**：
   - **零门槛检索**：基于 DuckDuckGo 零成本开箱即用，无需配置外部商业 API Key；
   - **内容去重**：MD5 内容指纹过滤镜像站重复；
   - **故障自愈**：WAF 阻断时自动降级到搜索摘要，或由 Agent 条件边重规划，完全避免无休止的爬虫对抗。
