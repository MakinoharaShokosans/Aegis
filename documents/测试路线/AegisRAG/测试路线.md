# AegisRAG 独立代码检索子系统测试路线图 (Test Roadmap)

> **定位**：`AegisRAG` 独立微服务子系统的全栈测试路线图，遵循"语法切分单元测试 → 向量化/存储引擎测试 → 精排与多路召回融合测试 → FastAPI 微服务契约测试 → 鲁棒性与 Preflight 探针测试 → 跨工程联调与 RAGBench 基线评测"的自底向上路线。
> **物理子工程**：`AegisRAG/`（独立虚拟环境与依赖空间，运行端口 `:8001`）。
> **核心原则**：纯 CPU/ONNX 离线优先、Qdrant 本地隔离、远端协议无网络依赖（`httpx.MockTransport` / 真实可选）、代码语法边界零破坏、数据幂等与失效清理零泄露。
>
> **图例规范**：`[代码实现] [测试通过]`
> - `[x] [x]`：**代码已实现** 且 **自动化测试已验证通过**
> - `[x] [ ]`：**代码已实现** 但 **自动化测试待编写/待通过**
> - `[ ] [ ]`：**规划中**，代码或评测尚未开始

---

## 0. 测试环境与基础设施规范

1. **虚拟环境隔离**：所有 RAG 相关的测试命令均在 `AegisRAG/` 子工程目录下执行（`cd AegisRAG && uv run pytest tests/`），严禁跨虚拟环境调用。
2. **零 GPU 与零外网强依赖**：
   - 默认模式下，FastEmbed（`jinaai/jina-embeddings-v3`、`Qdrant/bm25`、`TextCrossEncoder`）均使用本地 ONNX Runtime CPU 推理；
   - 远端模式（`mode="remote"`）单测通过 `httpx.MockTransport` 拦截模拟，无需真实外部 API Key 即可全量回归；真实外网联调作为单独标记的用例。
3. **Qdrant 存储沙箱隔离**：测试用例统一使用 `tmp_path` 临时目录初始化本地 Qdrant 存储（`storage_path=tmp_path / "qdrant"`），用例执行完毕自动销毁，严禁污染真实 `storage/`。
4. **Tree-sitter 测试语料就地隔离**：在 `AegisRAG/tests/fixtures/` 提供微型、典型的 C、C++、Go、Python、Markdown 代码片段，不依赖外部大型 Git 仓库。

## 2. Phase 1：语法感知切分与元数据契约测试 (`indexer/`)

目标：验证代码 AST 解析器、Markdown 结构切分器与通用降级切分器的语法边界完整性与元数据准确性。

- [x] **1.1 C/C++ AST 语法感知切分 (`tests/indexer/test_ast_splitter_c_cpp.py`)**
  - **函数边界**：切出完整 C/C++ 函数定义（`function_definition`），不腰斩函数体，行号（`start_line`/`end_line`）精准覆盖；
  - **结构体与类边界**：切出 `struct_specifier`、`class_specifier`、`enum_specifier`、`union_specifier`、`type_definition`；
  - **尾随分号吸收**：验证 `struct Point { int x; int y; };` 能够完整吸收结尾的 `;` 兄弟节点；
  - **预处理指令**：切出 `#define` 宏定义（`preproc_def` / `preproc_function_def`）；
  - **模板声明整体捕获**：验证 `template<typename T> class Foo { ... };` 作为一个整体切片，内部 `class` 不被重复切分；
  - **超大切片标记**：构造超过 `max_tokens`（`len(text)//4`）的代码块，验证 `oversized=True` 标记生效且不破坏语法结构。

- [x] **1.2 Go AST 语法感知切分 (`tests/indexer/test_ast_splitter_go.py`)**
  - **函数与方法**：切出普通函数（`function_declaration`）与结构体方法（`method_declaration`）；
  - **类型声明**：切出 `type_declaration`（如 `type Config struct { ... }`、`type Handler interface { ... }`）；
  - **尾随分号集合为空**：Go 语言无尾随分号吸收，验证切分边界准确截断。

- [x] **1.3 Markdown 标题层级切分 (`tests/indexer/test_markdown_splitter.py`)**
  - **H1~H3 层级切分**：多级标题文档正确按段落切出；
  - **面包屑路径注入**：切片携带 `enclosing_scope`（形如 `"架构设计 > 存储引擎 > Qdrant 选型"`）；
  - **顺序行号累加**：验证行号累加算法在规整文档下的单调递增性。

- [x] **1.4 降级切分与分发调度 (`tests/indexer/test_dispatch_and_fallback.py`)**
  - **Python 启发式切分**：`.py` 文件正确走 `Language.PYTHON` 切分路径；
  - **未识别扩展名定长切分**：纯文本、`.ini`、`.yaml` 走字符定长与 `chunk_overlap` 切分；
  - **非法语法容错与降级标记**：给 C 切分器传入语法严重破坏的代码，验证安全降级为 fallback 切分并在 `SplitOutcome.degraded=True` 记录；
  - **非代码/忽略文件过滤**：验证隐藏目录（`.git` 等）及二进制文件（UTF-8 解码失败）被自动过滤。

- [x] **1.5 `ChunkMetadata` 强类型契约校验 (`tests/indexer/test_metadata.py`)**
  - **必填项约束**：缺失 `file_path`、`start_line`、`end_line`、`content`、`language`、`repo_name` 时 Pydantic 拒绝构造；
  - **内容哈希**：`content_hash` 稳定输出 SHA-1 摘要；
  - **工厂方法 `ChunkMetadata.build()`**：自动计算哈希并安全设置预留字段。

## 3. Phase 2：双路向量化管道与维度探测测试 (`embeddings/`)

目标：验证 Dense 与 Sparse 向量生成的准确性、批处理分片与启动自检逻辑。

- [x] **2.1 本地 Sparse BM25 向量化 (`tests/embeddings/test_sparse_embedding.py`)**
  - **生成格式校验**：调用 `embed_sparse` 输出 `(indices, values)` 二元组，`indices` 为正整数列表，`values` 为正浮点权重；
  - **批处理一致性**：单条 `embed_sparse_one` 与批量 `embed_sparse` 生成结果完全一致；
  - **空输入处理**：传入空列表时返回空列表，不抛异常。

- [x] **2.2 本地 Dense ONNX 向量化 (`tests/embeddings/test_dense_local.py`)**
  - **维度与数值范围**：使用默认 `jinaai/jina-embeddings-v3` 生成向量，长度严格为 1024 维；
  - **分批处理逻辑**：传入超过 `batch_size`（如 30 条文本）的数据集，分批生成后顺序与原始输入完全对应。

- [x] **2.3 远端 Dense Embedding 协议与 Mock 测试 (`tests/embeddings/test_dense_remote.py`)**
  - **OpenAI 兼容协议组包**：验证 POST 请求发送到 `/embeddings`，请求体包含 `{"model": ..., "input": [...]}`，携带 `Authorization: Bearer <KEY>` 头；
  - **乱序响应重排序**：模拟服务端返回的 `data[].index` 无序列表，验证客户端能按原始请求顺序准确重排还原；
  - **网络异常与状态码转译**：模拟 401（未授权）、429（限流）、500（网关错误）及网络断开，验证抛出强类型 `UpstreamModelError(endpoint="embedding")`。

- [x] **2.4 启动期维度探测与自检 (`tests/embeddings/test_dimension_probe.py`)**
  - **`probe_dense_dimension()` 自检**：本地/远端模式下正确探测输出维度（1024 维）；
  - **密钥缺失预检**：`mode="remote"` 但环境变量缺失时，初始化阶段即抛出 `UpstreamModelError` 快速失败。

## 4. Phase 3：Qdrant 存储适配器与幂等增量机制测试 (`storage/`)

目标：验证 Qdrant Collection 结构初始化、启动强校验、确定性 UUIDv5 幂等去重与失效清理。

- [x] **3.1 Collection 生命周期与维度强校验 (`tests/storage/test_qdrant_lifecycle.py`)**
  - **自动创建**：初次启动时自动创建 Collection，正确配置 `dense`（Cosine/1024 维）与 `sparse` 向量空间；
  - **启动期维度不匹配拦截 (`DimensionMismatchError`)**：预先创建 768 维的 Collection，配置设为 1024 维，调用 `ensure_collection()` 必须抛出 `DimensionMismatchError` 且将 `collection_ready` 置为 False；
  - **健康快照**：`health_snapshot()` 正确返回 `mode`、`collection_ready`、`point_count` 与 `vector_size`。

- [x] **3.2 确定性 Point ID 与幂等性 (`tests/storage/test_ids_and_idempotency.py`)**
  - **`point_id_for` 确定性**：相同 `repo_name:file_path:start_line:content_hash` 多次计算返回相同 UUID 字符串；
  - **元数据微调敏感性**：`file_path` 或 `start_line` 变更返回不同 UUID；
  - **`existing_ids` 过滤**：验证已存在切片能被 `existing_ids` 批量识别并跳过。

- [x] **3.3 批量写入与分批处理 (`tests/storage/test_qdrant_upsert.py`)**
  - **混合写入**：同时写入 `dense` 向量、`sparse` 向量与 `ChunkMetadata` payload，读取点时 payload 结构完整无损；
  - **256 批次切片**：传入切片列表，验证底层 `upsert` 按批次正确提交；
  - **输入长度不匹配校验**：传入长度不等的 chunks 和 vectors 时抛出 `ValueError`。

- [x] **3.4 失效数据增量清理 (`tests/storage/test_stale_deletion.py`)**
  - **多文件覆盖更新**：仓库中有 `a.c`、`b.c`，第二次 ingest 仅包含 `a.c`，调用 `delete_stale(keep_file_paths=["src/a.c"])` 正确将 `b.c` 的切片全部清除；
  - **跨仓库数据隔离**：删除操作只影响目标 `repo_name`，不误删同 Collection 内其他仓库的数据。

## 5. Phase 4：Cross-Encoder 精排与多路召回融合测试 (`rerank/`)

目标：验证 Qdrant 原生 RRF 算子、本地/远端 Cross-Encoder 打分以及消融实验模式。

- [x] **4.1 Qdrant 原生 RRF (Reciprocal Rank Fusion) 混合召回 (`tests/rerank/test_hybrid_fusion.py`)**
  - **双路 Prefetch 融合**：Dense 与 Sparse 双路并发召回，RRF 融合输出前 `fusion_top_k` 项；
  - **语言过滤下推**：传入 `language="c"`，验证 `filter` 条件直接下推到 prefetch 查询层，召回结果中不包含其他语言切片。

- [x] **4.2 本地 Cross-Encoder 精排打分 (`tests/rerank/test_reranker_local.py`)**
  - **批量打分**：传入 query 与代码文本，验证相关文本得分显著高于不相关文本；
  - **空列表安全**：传入空文档列表返回空分数列表。

- [x] **4.3 远端 Rerank 协议与异常降级 (`tests/rerank/test_reranker_remote.py`)**
  - **`/rerank` 请求体构造与返回解析**：使用 `httpx.MockTransport` 验证 `{"model", "query", "documents"}` 格式正确性；
  - **按 `index` 还原顺序**：模拟乱序 results，验证按文档原序返回得分；
  - **网关故障转译**：模拟 502/503/超时，验证抛出 `UpstreamModelError(endpoint="rerank")`。

- [x] **4.4 调试与消融模式 (`tests/rerank/test_ablation_modes.py`)**
  - **`dense_only`**：仅使用 Dense 向量检索，跳过 Sparse 与 Rerank；
  - **`sparse_only`**：仅使用 BM25 稀疏向量检索；
  - **`hybrid`**：执行 RRF 双路融合检索。

## 9. 暂不纳入（未来增强路线）

- **RSE (Recursive Segment Expansion) 相邻段落动态缝合**：待 Phase 7 评测基线建立后，视收益情况开启；
- **MMR (Maximal Marginal Relevance) 多样性去重算法**：待召回阶段需要解决高相似重复切片时开启；
- **多 Qdrant 节点分布式分片集群**：当前单机本地/微服务模式已完全满足单机百万级切片性能要求。
